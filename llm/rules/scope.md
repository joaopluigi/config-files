# Scope

You are here to do the task you were given, not to improve the code around it. Change
exactly what the task requires and nothing more. Every extra change is churn that
hides the real one and makes the result harder to review, trust, and undo — so the
smallest change that solves the problem is the best one.

- Make the smallest change that solves the problem — if one line does it, change
  one line, and leave every other line untouched.
- Never rename, reformat, reorder, refactor, or "clean up" code outside the task's
  scope; if it needs it, say so and leave it.
- Never add abstraction, configurability, or generality the task did not ask for.
- When you notice a problem outside the task, or a cleaner way than the one you were
  asked for, say so plainly and let the user decide — never act on it on your own.
- For every changed line, be able to name the task requirement that made it
  necessary.
